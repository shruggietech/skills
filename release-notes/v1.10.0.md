# v1.10.0 - 2026-08-22

## Added

- `shruggie-powershell`: new `PII gate` in `SKILL.md` and a matching `PII and Operator Context`
  section in `assets/powershell-conventions.md` instruct Claude to never hardcode operator-specific
  literal context (a real-username path, a personal email, family or personal detail, an
  operator-machine hostname) surfaced in conversation into a generated script, and instead
  parameterize it, derive it from the environment, or ask. `Test-ScriptCompliance.ps1` and
  `test-script-compliance.sh` gain a matching advisory (never-failing) `WARN` scan for
  username-bearing paths and email-address-shaped strings, opt-out via `-SkipPiiCheck` /
  `--skip-pii-check`. `Test-ScriptCompliance.ps1` also gains an AST-based advisory scan flagging
  function names whose verb is outside PowerShell's approved-verb list (`Get-Verb`), opt-out via
  `-SkipVerbCheck`; this check is PowerShell-twin-only since it needs a live `Get-Verb` session.

## Fixed

- `shruggie-powershell`: reverses the documented policy that told Claude to ignore
  PSScriptAnalyzer's `UseApprovedVerbs` rule and claimed `Import-Module -DisableNameChecking`
  suppressed it. Neither was true: `UseApprovedVerbs` (and `UseSingularNouns`) are "Always
  enabled" / "Enabled" defaults not configurable project-wide, and `-DisableNameChecking` only
  silences a session-level `Import-Module` warning, never PSScriptAnalyzer's static diagnostic
  (the thing that actually shows up in the VS Code PowerShell extension and CI lint pipelines).
  `Get-CryptoBytes` (plural noun, a real `UseSingularNouns` violation produced by exactly this
  policy) is renamed to `Get-CryptoByte` throughout `assets/powershell-conventions.md` and
  `assets/examples/Get-Secret.ps1`. `SKILL.md` and the conventions doc now require an approved
  verb and a singular noun for every function name, with a synonym table for common near-misses
  (Print/Put, Delete/Eliminate, Validate/Verify/Check, Create/Build/Make, Fetch, Load, Change).
